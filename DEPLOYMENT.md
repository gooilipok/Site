# Единое руководство по развёртыванию и обновлению проекта BauSquad

Данный документ содержит исчерпывающую инструкцию по развёртыванию, сборке и обновлению сайта **BauSquad** на VPS / выделенном сервере (включая хостинг **nic.ru / Ru-Center**).

---

## 📌 1. Детальная настройка внешних сервисов в `.env`

Перед запуском или пересборкой проекта убедитесь, что в файле `.env` прописаны корректные переменные для подключения к вашей развёрнутой базе данных, Telegram-боту и Telegram-каналу.

### 🗄️ А. База данных MySQL (`bau7824897_db`)
База данных уже развёрнута и функционирует на хостинге. Изменять её структуру (схему) не требуется. Приложение подключается к ней автоматически при старте.

Параметры в `.env`:
```env
# Параметры подключения к MySQL
MYSQL_HOST="mysql.hosting.nic.ru"
MYSQL_PORT=3306
MYSQL_DATABASE="bau7824897_db"
MYSQL_USER="bau7824897_mysql"
MYSQL_PASSWORD="ВАШ_ПАРОЛЬ_К_БД_ИЗ_ПАНЕЛИ_ХОСТИНГА"

# Альтернативная строка подключения (используется как fallback)
DATABASE_URL="mysql://bau7824897_mysql:ВАШ_ПАРОЛЬ_К_БД_ИЗ_ПАНЕЛИ_ХОСТИНГА@mysql.hosting.nic.ru:3306/bau7824897_db"
```
> **Что происходит:** При создании заказа (как авторизованным клиентом, так и гостем) данные мгновенно записываются в таблицы `users`, `orders`, `payments` и `support_requests`.

Приложение пересылает данные обо всех новых заказах, изменениях статусов, ценах и обращениях в поддержу в администраторский Telegram-чат или канал.

Параметры в `.env`:
```env
# Токен бота (получен от @BotFather в Telegram)
TELEGRAM_BOT_TOKEN="8655510215:AAHD2y49HbYoXn1lXVbu81sf77Ng9rUPuW8"

# ID Telegram-канала или чата, куда пересылаются данные (начинается с -100 для супергрупп и каналов)
TELEGRAM_ADMIN_CHAT_ID="-1003817358324"
```

#### Пошаговая инструкция по настройке Telegram-канала/чата:
1. **Создайте Telegram-канал или чат** (или используйте существующий администраторский чат).
2. **Добавьте Telegram-бота** (созданного в `@BotFather`) в члены вашего канала/чата.
3. **Назначьте бота Администратором** канала/чата с правом **Публикации сообщений (Post Messages)**.
4. **Узнайте ID канала/чата**:
   - Перешлите любое сообщение из канала боту `@myidbot` или `@username_to_id_bot`.
   - В ID закрытых каналов и супергрупп в начале обязательно стоит `-100` (например: `-1003817358324`).
5. **Укажите полученный ID** в файле `.env` в переменной `TELEGRAM_ADMIN_CHAT_ID`.
6. **Перезапустите проект** (`pm2 restart bausquad`).

> **Куда пересылаются данные:**
> - 📚 **Новые заказы**: Наименование предмета, описание работы, дедлайн, контакт клиента, признак гостя и подтверждение согласия с 3 законами РФ.
> - 🔔 **Изменения статусов**: Мгновенное информирование администраторов при переходе заказа в «В работе», «Готов» и т.д.
> - 💰 **Расчёт стоимости**: Клиентская цена и выплата исполнителю.

## 📌 2. Главная особенность сборки (`docs/`)

Проект настроен так, что клиентский бандл фронтенда компилируется в папку **`docs/`** (вместо стандартной `dist/`). Это сделано для совместимости с требованиями хостингов (включая nic.ru / Ru-Center), которые по умолчанию ожидают статические файлы веб-сайта в директории `docs/` или `public_html/`.

В `server.ts` реализована встроенная логика отдачи статики: сервер автоматически ищет скомпилированные файлы в папке `docs/` и отдает `index.html` оттуда.

## 🛠 3. Первичное развёртывание на VPS / Хостинге

### Шаг 1. Подключение по SSH и клонирование
```bash
# Подключение к вашему серверу
ssh YOUR_USERNAME@YOUR_SERVER_IP

# Переход в рабочую директорию хостинга
cd ~/bausquad

# Загрузка проекта из вашей ветки GitHub
git clone https://github.com/YOUR_USERNAME/bausquad.git .
```

### Шаг 2. Настройка файла окружения `.env`
Создайте файл `.env` в корне проекта:
```bash
nano .env
```
Вставьте сохраненные параметры подключения к MySQL, Telegram и SMTP (из раздела 1).

### Шаг 3. Установка зависимостей и сборка в `docs/`
```bash
# 1. Установка всех пакетов
npm install

# 2. Сборка фронтенда в папку docs/ и сервера в dist/server.cjs
npm run build
```

### Шаг 4. Запуск сервера приложения Node.js

#### Вариант А: Через PM2 (Рекомендуется)
```bash
# Установка PM2 в профиль текущего пользователя (без root)
npm install -g pm2

# Запуск приложения
pm2 start dist/server.cjs --name bausquad

# Сохранение списка процессов
pm2 save
```

#### Вариант Б: Через `nohup` (если нет PM2)
```bash
nohup node dist/server.cjs > app.log 2>&1 &
```

## 🔄 4. Инструкция по обновлению сайта при новых коммитах

Когда вы вносите изменения в код локально и отправляете их в GitHub (`git push`), выполните следующие команды на вашем VPS:

```bash
# 1. Переход в папку проекта
cd ~/bausquad

# 2. Получение свежего кода из репозитория
git pull origin main

# 3. Обновление зависимостей (если добавлялись новые библиотеки)
npm install

# 4. Пересборка проекта в папку docs/
npm run build

# 5. Перезапуск приложения Node.js
pm2 restart bausquad
# Или при использовании nohup:
# pkill -f "node dist/server.cjs" && nohup node dist/server.cjs > app.log 2>&1 &
```

## 🔍 5. Диагностика и проверка работы

1. **Проверка статуса процессов PM2**:
   ```bash
   pm2 status
   pm2 logs bausquad --lines 50
   ```
2. **Проверка API проверки работоспособности**:
   Зайдите в браузере по адресу `https://www.bausquad.org/api/health` — ответ должен быть `{"status":"ok"}`.
3. **Файлы статики**:
   Убедитесь, что папка `docs/` создана и содержит файл `index.html` и каталог `assets/`.
4. **Проверка работы без демо-элементов**:
   - Все тестовые кнопки смены ролей и подсказки с демо-паролями удалены.
   - Коды верификации отправляются исключительно на указанную почту.
   - Все заказы сохраняются в онлайн-базу MySQL и немедленно пересылаются в Telegram-канал.

## 🌐 6. Устранение ошибки 404 (Not Found) на `/api/auth/register`

Если при нажатии кнопки «Зарегистрироваться» в консоли браузера появляется ошибка:
`POST https://bausquad.org/api/auth/register 404 (Not Found)`

Это означает, что веб-сервер хостинга (Nginx или Apache на `nic.ru`) отдаёт статику из папки `docs/` напрямую и **НЕ перенаправляет запросы с префиксом `/api/` на запущенный сервер Node.js (порт 3000)**.

### Вариант 1. Настройка Nginx (Рекомендуется для VPS)
В файле конфигурации вашего сайта Nginx (например `/etc/nginx/sites-available/bausquad.conf` или в панели Nginx) перенаправьте ВСЕ запросы к `/api/` на Node.js:

```nginx
server {
    listen 80;
    server_name bausquad.org www.bausquad.org;

    # Вариант А: Перенаправление ВСЕГО трафика на Node.js (Express сам отдаёт статику из docs/)
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # Вариант Б: Если Nginx отдаёт статику сам из docs/
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
После внесения изменений выполните перезагрузку Nginx:
```bash
sudo nginx -t && sudo nginx -s reload
```

### Вариант 2. Настройка `.htaccess` для Apache (Хостинг nic.ru)
Если ваш веб-сервер на хостинге `nic.ru` работает под управлением Apache, создайте файл `docs/.htaccess` со следующим содержанием:

```apacheconf
RewriteEngine On

# Проксирование всех запросов к API на Node.js (порт 3000)
RewriteRule ^api/(.*)$ http://127.0.0.1:3000/api/$1 [P,L]

# Перенаправление остальных запросов на index.html для SPA
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.html [L]
```

### Вариант 3. Проверка запуска процессов на сервере
Убедитесь, что Node.js процесс активен и слушает порт 3000:
```bash
# 1. Проверка статуса PM2
pm2 status

# 2. Если процесс упал, перезапустите
pm2 restart bausquad

# 3. Проверка локального ответа API прямо с сервера
curl -I http://127.0.0.1:3000/api/health
# Должен вернуть HTTP/1.1 200 OK
```
